Overview

Edit a definition with the Visual forms, or write it in YAML. It describes a picture made of shapes, plus zooms: smaller copies of the whole picture placed inside itself. Each copy contains its own copies, and so on, which makes a fractal.

A definition has these parts. Only scene is required.

info:       # title, author and other details for the label
variables:  # named numbers to use in expressions
frame:      # the border drawn around the picture
view:       # picture size and coordinates
seed:       # colour of the smallest copies
shading:    # colour by paint (normal) or by density
scene:      # the shapes and zooms, in drawing order

Indentation matters in YAML. Lists use - at the start of each item. Text after # is a comment. Colours are any CSS colour, such as red or "#336699" (put quotes around colours that start with #, or YAML treats them as comments).

This guide uses British spellings, but American ones also work: color for colour, colors for colours, and center for centre (including in references like base.center and view.center.x). A misspelt or unknown setting is a mistake, and the message suggests the closest known name.

Mistakes are shown in red, and the last valid picture stays visible while you repair them. YAML also underlines mistakes as you type; hover over one to see what is wrong.

Automatic quality renders enough levels for the smallest visible details, and keeps going while the picture is still visibly changing, such as when see-through shapes let deeper levels show, up to a safety limit. If it reaches that limit first, a warning appears beside Render settings. Use +256 levels there to continue the current picture without starting over. Each click allows another 256 levels, stopping sooner once the picture settles; changing the picture or quality starts fresh.

Quality also controls output resolution. Fast draws at half the display's physical resolution, Display matches it, High quality is 1500 pixels high, and Print is 3600 pixels high. Custom lets you give either width or height; the other dimension follows the scene's aspect and is shown in grey. Entering a value in that field makes it the controlling dimension instead. If the supersampled working image exceeds either the device's WebGL texture size or ZoomFract's practical GPU capacity limit, the output is reduced proportionally and a warning appears beside Render quality.

ZoomFract draws with WebGL2, which all current browsers support. If it is turned off or the graphics card fails, an error explains why.

Editor

Visual is the default editor. Expand a section to edit picture information, frame and wall, view, seed, shading, or variables. Use Add setting for optional settings; removing a setting restores its normal default. Number fields accept expressions, including variables. Colour fields accept CSS colours and expressions in rgb(), just like YAML.

Render quality appears with the Visual sections, or above the YAML editor. It is still an app setting, not part of the saved YAML definition.

In Scene items, use the + menu on the heading to add a rectangle, circle, polygon or zoom. Click an item's heading to expand its settings. Drag its heading to change the drawing order; a horizontal line shows where it will be inserted. On touch screens, hold the heading for one second until the item lifts before dragging; swiping without holding scrolls normally. A faded copy of the heading follows the mouse or finger while dragging. The arrows and bin on the right of the heading move or delete the item. Alt+Up and Alt+Down also reorder an item while its heading has focus. Later items draw on top of earlier ones. Undo and Redo can restore removed settings and items.

Expanding an item shows its outline and any zoom alignment points on a transparent overlay. This does not redraw or fade the picture, and the overlay is not included in shared images or exports. When overflow makes the canvas differ from the declared view, a zoom has a dashed outline for its copy of the declared view and a same-colour dotted outline for its copy of the whole canvas. Closing the item, closing Scene items or switching to YAML removes the highlight.

Visual edits update the picture after a short pause. The Visual and YAML tabs share one draft, including expressions, references and comments. YAML edits wait for Apply scene or Ctrl+Enter, or are applied when switching back to Visual. If YAML has a syntax error, repair it in the YAML tab before using the forms. Neither mode replaces the last valid picture with an invalid definition.

Info

Details about the picture, shown on a label beside it like in a gallery. Every setting is optional, and none of them change the picture. 

info:
  title: Vicsek Red Blue
  author: Emlyn Corrin
  date: 2026-09-26        # any text, such as "Spring 2026"
  description: >
    A Vicsek cross with red and blue
    glows on alternate arms.
  links:
    - https://en.wikipedia.org/wiki/Vicsek_fractal
    - title: PowerPoint Fractals
      url: https://github.com/emlyn/PowerPointFractals
  • Links are web addresses starting with http:// or https://, with an optional title to show instead.
  • The label also gives the picture's size in pixels, what it is made of, and how many levels were rendered.
  • It also gives the fractal dimension of the shape the zooms make, which says how quickly detail fills space: 1 for a line, 2 for a filled area, and in between for fractals. When the copies do not overlap, or overlap only by chance, it is exact, written as a formula where possible, such as log(3) / log(2) ≈ 1.585 for Sierpinski's triangle. Otherwise it is estimated, shown with two decimal places. Copies that land exactly on top of each other count once. When overlapping copies lower the dimension, the label also gives the similarity dimension: what it would be if no copies overlapped. For a picture of a 3D fractal, such as the Menger sponge, that is usually the dimension of the 3D shape itself.
  • The label goes beside the picture, or underneath when that leaves more room. Turn it off with Show label in Frame and wall.
  • On narrow screens, input controls go below the picture and above the label. Scroll vertically to reach the cards when they do not fit on screen.
  • For built-in examples, the title and description also appear in the example list.

View

The view sets the shape of the picture and its coordinates. Quality controls its pixels.

view:
  aspect: 4/3          # width divided by height
  coordinates:
    x: [-4, 4]         # left edge, right edge
    y: [-3, 3]         # bottom edge, top edge
  • aspect is the width divided by the height. The default is 1 (square). aspect: auto takes it from the coordinates, so one unit is the same length across and up.
  • coordinates sets the numbers used to place things. x goes from left to right, and y goes from bottom to top, as in maths. Ranges can also be written { from: -4, to: 4 }. The default is -100 to 100 on both axes.
  • overflow adds a border, in coordinates, around every side of the view. Nothing is placed by it, but it shows anything that spills past the edges, such as glows. Each zoom's copy includes the border too, so zooms draw slightly bigger than their size. The seed still only fills the part of each copy inside the view, not the border. The default is 0. In edit mode the view edge is shown as a grey dashed line.
  • overflow: auto fits the picture to everything the scene draws, however far the zooms spread it, so nothing is cut off and nothing is wasted. The view is grown or shrunk evenly about the content, keeping its aspect, and the short side is padded equally on both sides. With aspect: auto as well, each side is fitted separately, so the picture takes the shape of the content with no padding. Shapes are clipped to the view before they are copied, so parts outside it do not add empty space to the fit. The coordinates still set what each zoom copies, so the shape is the same as without it. Every zoom must be smaller than the view, or the picture would grow forever.

Frame

The frame only changes how the picture is shown on the page, not the picture itself. Sizes are in screen pixels.

frame:
  width: 12            # border thickness
  radius: 6            # rounded corners
  colour: "#444"        # border colour
  wall: "#ddd"         # colour of the page around the frame
  background: "#fff"   # colour behind the picture
  padding: 12          # space between border and picture
  margin: 24           # space between frame and window edge

The border, wall and margin are not part of the picture. Shared images are drawn on the background colour, unless you tick Transparent background, which leaves them transparent wherever nothing is drawn.

Scene

The scene is a list of items. Each item has a type, either rect, circle, polygon or zoom. Items are drawn in order, so later items appear on top of earlier ones.

Any item may have a name, so other items can refer to its points. Names must be unique, cannot contain dots or spaces, and cannot be view.

Shapes

- type: rect
  name: block
  centre: [0, 0]
  width: 2
  height: 1
  rotation: 30         # degrees, clockwise
  colour: "#d97757"
  opacity: 0.8         # 0 is invisible, 1 is solid

Rectangles are filled with colour (black by default) and have no outline. opacity defaults to 1. With density shading, use weight instead.

Circles use a centre and radius, or exactly three points on the circumference:

- type: circle
  centre: [0, 0]
  radius: 1
- type: circle
  points: [[-1, 0], [1, 0], [0, 1]]

A polygon lists its corner points in order, or can be regular: give its number of sides, centre and one vertex. The vertex sets both its radius and orientation. 

- type: polygon
  points: [[0, 0], [2, 0], [2, 1], [1, 1.5], [0, 1]]
- type: polygon
  sides: 6
  centre: [0, 0]
  vertex: [0, 1]

Listed polygon points must form a simple shape: edges cannot cross or touch. Points can refer to another named shape, for example shape.points.0. Circles and polygons use the same colour, opacity and density-weight settings as rectangles.

Anywhere a colour is used, write a name such as teal, a hex code (#rgb, #rgba, #rrggbb or #rrggbbaa), or a function such as rgb(255 0 0 / 50%), rgba(255, 0, 0, 0.5), hsl(200 60% 50%) or oklch(70% 0.1 200). A colour's own transparency combines with opacity.

The three comma-separated channels in rgb() may also be expressions, such as rgb(68 * mix, 204 * mix, 68 * mix). Channels use numbers from 0 to 255, or expressions ending in % for percentages. Other colour functions use ordinary CSS syntax.

Anywhere opacity is allowed you can write transparency instead, which is 1 minus the opacity (use one or the other). Both take a number from 0 to 1 or a percentage, so opacity: 80% and transparency: 0.2 are the same.

Position and size

Rectangles and zooms are placed the same way. Give enough of these to fix exactly one rectangle:

  • centre: the middle point
  • topLeft, topRight, bottomLeft, bottomRight: corners
  • width and height
  • rotation: clockwise turn around the centre

Some combinations that work:

  • centre, width and height
  • one corner, width and height
  • two opposite corners, such as bottomLeft and topRight
  • two corners along one edge, plus the other size (the edge sets the rotation)
  • three corners (they set the size and rotation)

rotation can be added to most of these. Without it, the rectangle is not rotated unless the corners say otherwise. If the values are not enough, or they disagree, an error explains which item is wrong.

Rotation can be written in several ways:

rotation: 30              # degrees
rotation: 30deg           # degrees
rotation: pi/6 rad        # radians
rotation: { radians: 0.5 }
rotation: { degrees: 30 }

Points

A point can be written as a pair, an object, or a reference to another item.

centre: [1, 2]
centre: { x: 1, y: 2 }
centre: block.topRight    # a point of the item named block
centre: view.centre       # a point of the whole view

References use name.part, where the part is centre, top, bottom, left, right (edge middles) or a corner: topLeft, topRight, bottomLeft, bottomRight. Points follow the item's rotation. Items can refer to items defined later, as long as they do not refer to each other in a loop.

Zooms

A zoom is a rectangle that holds a copy of the whole view: everything in the scene, including the zooms themselves. The top left of the view lands on the zoom's top left corner, and so on. 

- type: zoom
  centre: [0.5, 0.5]
  scale: 0.5          # half the size of the view
  rotation: 15
  • Zooms are placed like rectangles, but have no colour.
  • scale gives the size as a fraction of the view. It cannot be used together with width or height.
  • If only width or height is given, the other comes from the view's aspect, so the copy is not stretched.
  • opacity fades the copy (not with density shading).
  • blend chooses how the copy mixes with what is below it: normal (the default) paints over it, multiply darkens, screen lightens, add adds the colours together, darken keeps the darker colour and lighten the lighter one. Blending is not used with density shading or in PowerPoint files, and pictures with blended zooms build every level from the one before, so they can look slightly softer.

Alignment

align places a zoom by saying where a point of the full picture should end up in the copy. Each pair is [from, to]: from is a point in the full picture, and to is where that point's copy should go. 

- type: rect
  name: stem
  bottomLeft: [-0.11, -1]
  topRight: [-0.09, -0.7]
- type: zoom
  scale: 0.86
  rotation: -2
  align: [stem.bottomLeft, stem.topLeft]

Here, the copy's version of the stem starts where the real stem ends, so the stem grows upwards. With one pair, also give scale, width or height (and optionally rotation).

With two pairs, the zoom's size and rotation are worked out too:

align:
  - [view.bottomLeft, stem.topLeft]
  - [view.bottomRight, stem.topRight]

Pairs can also be written { from: ..., to: ... }.

Seed

Copies inside copies get smaller and smaller. When they become too small to see, they are drawn as a plain rectangle in the seed colour instead. The seed is transparent by default. 

seed: "#111827"

seed:
  colour: "#111827"
  opacity: 0.9

Glow

Rectangles and zooms can have a soft glow around them, like PowerPoint's glow effect. The glow is drawn just underneath the item, on top of anything earlier. 

- type: rect
  centre: [0, 0]
  width: 1
  colour: "#3b82f6"
  glow:
    colour: "#fde047"  # required
    opacity: 0.6       # defaults to 1
    size: 0.1          # how far it spreads, in coordinates; 0 adds no spread
    softness: 0.3      # 0 is a solid band, 1 (the default) fades over the whole size

Zoom glows also accept sourceOpacity, from 0 to 1 (or a percentage). It controls how much transparency in the copied picture reduces the glow: 0 (the default) ignores source transparency when forming the glow, closer to PowerPoint, while 1 keeps the current alpha-weighted glow. Use values in between to blend the behaviours. The glow's own opacity still controls its strength independently. 

  glow:
    colour: cyan
    size: 0.005
    opacity: 0.5
    sourceOpacity: 0.25
  • A zoom's glow follows the shapes in its copy.
  • At size 0, a zoom glow still follows the source shape; it can show behind a translucent copy.
  • Glow size is part of the scene, so it stays proportional when quality changes.
  • Glows are copied into zooms along with everything else.
  • Glows are cut off at the edge of the picture; add a view overflow, or overflow: auto, to make room.
  • Glows cannot be used with density shading.

Shading

Normally, shapes are painted on top of each other (mode: paint). When copies become smaller than a pixel, detail chooses how they are shrunk: 

shading:
  detail: average            # average (default), preserve, or -1 to 1
  • average (or 0) blends tiny details into their surroundings, like ordinary image scaling and PowerPoint. Faint, overlapping copies stay faint.
  • preserve (or 1) keeps tiny details bold so thin lines do not fade away, but areas with many see-through copies can turn dark.
  • Numbers between give a mix, for example 0.5 or 50%. Negative numbers, down to -1, do the opposite: tiny details fade away faster, leaving only solid areas.

Density shading

Painted busy areas can still turn solid. Density shading instead counts how many shapes and copies cover each pixel, and colours the pixel by that count. This keeps detail where many copies overlap. 

shading:
  mode: density              # paint (default) or density
  scale: log                 # log (default), sqrt or linear
  colours: [white, orange, "#1e1b4b"]
  • colours has 2 to 8 colours, from few hits to many hits. A list spreads them evenly. To choose where each colour goes, map positions to colours instead. A plain number is a hit count, and a percentage is how far along the scale it is, where 100% is the busiest pixels: 
    colours:
  1: "#fef3c7"     # covered once
  3: orange        # covered three times
  60%: "#b91c1c"
  100%: "#1e1b4b"
    Below the first position the first colour is used, and above the last position the last colour is used.
  • scale controls how counts become colours. log shows the most detail in busy areas, linear the least.
  • Pixels that nothing covers stay transparent.
  • Counts are compared with the busiest pixels in the picture, so the colours adjust to the scene automatically.

Shapes do not have colour or opacity in this mode. Instead, weight (1 by default) says how much each shape counts. Zoom opacity and seed are not used.

Expressions

Anywhere a number is expected, you can write a calculation instead.

aspect: 2/sqrt(3)
width: 1/phi
x: [-4/3, 4/3]
rotation: 360/5
centre: [0, "root(3, 2)"]   # quote it if it contains a comma inside [ ]
Operators+ - * / ^ and brackets ( ). ^ is power. There is no hidden multiplication: write 2*pi, not 2pi.
Constantspi, e, phi (the golden ratio, about 1.618)
Rootssqrt(x), root(n, x) (the nth root of x)
Logslog(x) and ln(x) (both natural log), exp(x)
Trigonometrysin, cos, tan, asin, acos, atan, atan2(y, x), all in radians
Otherabs(x); min(a, b, ...) and max(a, b, ...) choose the smallest or largest of one or more values

-2^2 is -4, because the power is worked out first. Use brackets to make things clear, such as (-2)^2.

Variables

Variables give a name to a number, so it can be used in expressions.

variables:
  - name: s
    value: 1/sqrt(2)
  - name: gap
    value: s/10

scene:
  - type: zoom
    centre: [0, gap]
    scale: s

Names start with a letter or _, and may contain letters, digits and _. They cannot be the same as a constant or function, such as pi or sin. Variables can use each other in any order, as long as they do not depend on each other in a loop.

Inputs

A variable with an input can be changed while viewing the picture. Its controls appear on a card beside the picture, and value is where it starts. 

variables:
  - name: size
    value: 0.6
    input: { type: slider, min: 0.3, max: 0.9, label: Square size }
  - name: apex
    value: [1.55, 1.2]
    input: drag

scene:
  - type: zoom
    align:
      - [base.bottomLeft, base.topLeft]
      - [base.bottomRight, [apex.x, apex.y]]

The Triangle to Fern example uses a slider from 0 to 1 to blend two pictures. Expressions of the form (1 - mix) * start + mix * end interpolate each zoom's scale, translation and rotation. The stem's opacity and length follow mix. The stem and faint seed change colour from black to green. The view stays fixed throughout the transition, with the fern centred. Zero-size zoom glows keep fine detail bold, changing from black to green with the slider without extending past the picture's shapes. A checkbox multiplies the stem's opacity to hide it.

slidera number between min and max, with an optional step between values. These may be expressions.
clicka point, moved to wherever the picture is clicked
draga point that follows the pointer while the button is held down
checkboxa value of true or false, switched by ticking a box
  • A point's value is [x, y] in view coordinates. Use it in expressions as apex.x and apex.y.
  • Any variable may be true or false, which count as 1 and 0 in expressions. For example, opacity: mix * showStem hides a shape when showStem is false.
  • With more than one point, pressing the picture moves the nearest one. Write input: drag as a shortcut for input: { type: drag }.
  • label is the name shown on the card; it defaults to the variable's name.
  • While a value changes, the picture is previewed quickly, then drawn at the chosen quality once it settles. Reset goes back to the values in the definition.
  • Values are kept when the edited definition is applied, and reset when another definition is loaded, unless it is a shared link that includes them.

View values

Expressions can also use these values from the view:

view.left, view.rightx of the left and right edges
view.bottom, view.topy of the bottom and top edges
view.width, view.heightsize of the view in coordinates
view.centre.x, view.centre.ymiddle of the view
view.aspectwidth divided by height
view.overflowborder around the view in coordinates
view:
  aspect: 3/2
  coordinates:
    x: [-view.aspect, view.aspect]
    y: [-1, 1]

A view value cannot be used to define itself. For example, the x range can use view.aspect but not view.width.

Note the difference between view.centre, which is a point (used as centre: view.centre), and view.centre.x, which is a number (used in expressions).

Sharing

The share icon at the top of the settings panel or on the picture label opens a window with five tabs:

  • Image copies or downloads the picture as a PNG, at full size or smaller, optionally with a transparent background. These wait until rendering has finished.
  • Link copies a link that contains the applied definition, so it shows the same picture without needing to be saved anywhere. It can include the current input values, and the app settings: quality, render settings and whether the label is shown. Edits that have not been applied are not included.
  • QR code shows the link as a QR code to copy or download, with the same options as the link. By default it includes a small preview of the drawn part of the picture in the centre; the code is then made more robust so it still scans. Click the code to see it larger, and again to go back.
  • Definition downloads the applied definition as a YAML file, or opens one you saved earlier. You can also drop a YAML file anywhere on the window to load it.
  • PowerPoint downloads a one-slide presentation of the top level of the scene. Shapes become PowerPoint vector shapes, and each zoom becomes a Slide Zoom of the slide itself, so PowerPoint draws the repeats. Density shading, zoom opacity and glow softness are not carried over, and the tab lists any the scene uses. When only the seed draws anything, PowerPoint can fade the picture away as it updates the zooms; covering the slide with a rectangle in the seed colour and deleting it brings it back. This waits until rendering has finished, because the zooms start out showing the picture.

Clicking the picture on the Image tab shows it larger too, and Ctrl+C copies whatever the open tab shows unless you have selected some text.

The definition is compressed to keep links short. Definitions that are similar to the examples give the shortest links.

  - type: ellipse
  centre: [0, 0]

Images

- type: image
  source: https://example.com/leaf.png
  centre: [0, 0]
  width: 2                 # the height follows the image's shape
  crop: { left: 10%, right: 90%, top: 0, bottom: 400 }   # pixels or percentages
  fit: cover               # fill, contain or cover, when both sizes are given
  smooth: false            # keep pixel art sharp

Images are placed like rectangles. The site must allow other pages to use its images; if it does not, an error says so.

Groups and combining

- type: group
  name: window
  combine: difference      # union, intersection, difference or xor
  colour: "#335"
  items:
    - type: rect
      width: 4
      height: 3
    - type: circle
      radius: 1
  • With combine, the items only give the shape, and the result is filled with the group's colour. difference takes the other items away from the first. add, overlap, subtract and exclude are other names for the four ways.
  • Without combine, the items are drawn in order, and the group's opacity and glow apply to them all together.
  • A group can be moved as a whole with move, rotation, scale and flip, turning and scaling about a point, which is the middle of its items unless given.
  • clip keeps only the part of a group or zoom inside a shape: 
- type: zoom
  centre: [0, 0]
  scale: 0.5
  clip:
    type: circle
    centre: [0, 0]
    radius: 0.4

Gradients

Any colour of a shape can be a gradient instead:

colour:
  gradient: linear         # linear, radial or conic
  from: block.left
  to: block.right
  colours: [red, "#fde047", blue]

colour:
  gradient: radial
  centre: block.centre
  radius: 1
  colours:
    0%: white
    70%: "#93c5fd"
    100%: "#1e3a8a"

colour:
  gradient: conic
  centre: [0, 0]
  angle: 90
  colours: [red, yellow, lime, cyan, blue, magenta, red]
  repeat: mirror           # none, repeat or mirror

colours is written like the density shading colours. Without from and to (or centre), a gradient spans the shape's own box, so it turns and shrinks with it in every copy.

Zooms

- type: zoom
  centre: [0, 0.5]
  scale: 0.6
  flip: horizontal         # horizontal, vertical or both
  depth: 5                 # copy at most 5 levels deep
  tint:
    colour: "#f97316"
    amount: 0.2
  hue: 15                  # degrees around the colour wheel
  brightness: 0.9
  saturation: 1.1

Colour changes build up: a copy inside a copy is tinted twice. An align with three pairs can also stretch, slant or mirror a copy.

Repeats and hidden items

- type: repeat
  count: 6
  rotation: 60             # each copy turns a further 60 degrees
  about: [0, 0]
  items:
    - type: rect
      centre: [0, 1]
      width: 0.2
      height: 0.5
      opacity: 1 - index/10  # index counts the copies from 0
- type: rect
  name: guide
  hidden: true             # only shown in edit mode, but can be referred to
  bottomLeft: [-1, -1]
  topRight: [1, 1]
